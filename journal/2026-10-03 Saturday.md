### What I learned
- `nano` is a **terminal text editor**. It lets you create and edit files directly from the command line, without a graphical interface.
	- Read a config file and make a decision about what to change.
	- Edit multiple lines in different places.
	- Write a script from scratch.
	- Look at a file interactively before changing it.
- **On real servers, `nano` is often the default.** If you SSH into a fresh Ubuntu server and try `vim`, you might find it's not installed. `nano` almost always is.
- **Security relevance:** When you're on a compromised server during an investigation, you may need to edit config files, fix SSH settings, or add firewall rules — and `nano` is what's available.
- `nano myfile.txt`
	- If `myfile.txt` exists, `nano` opens it.
	- If it doesn't exist, `nano` creates it (when you save).
	- When you open `nano`, you see:
		- **Top:** The file contents (or empty for a new file).
		- **Bottom:** A menu of commands with `^` symbols.
	`^` means **Ctrl**. So `^O` means **Ctrl+O**.
The most common commands (always shown at the bottom):

|Shortcut|What it does|
|---|---|
|`^O`|Save (Write Out)|
|`^X`|Exit|
|`^W`|Search (Where Is)|
|`^K`|Cut current line|
|`^U`|Paste (Uncut)|
|`^G`|Help|
- Search (`Ctrl+W`)
	- `Ctrl+W` = **Where Is** (search).
	- Type a search term, press Enter.
	- The cursor jumps to the first match.
	- Press `Ctrl+W` again and Enter to search for the same term (find next).
	- Press `Alt+W` to search for the next occurrence without retyping.
	**Security use:** In a large config file, search for `PermitRootLogin`, `PasswordAuthentication`, or any suspicious directive.
- Cut and Paste (`Ctrl+K` / `Ctrl+U`)
	- `Ctrl+K` = **Cut** from cursor to end of line.
	- `Ctrl+U` = **Paste** (Uncut) the last cut line at the cursor.
	**Note:** `nano`'s cut/paste is line-based. To copy (not cut), use `Alt+6` (copy line) instead of `Ctrl+K`.
	**Practical use:**
	- Reorder lines in a config file.
	- Move a block of text to a different location.
    - Delete a line quickly (Ctrl+K without pasting).
- Why learn `vim` if `nano` exists?
	1. **`vim` is on more systems than `nano`.** Some minimal server installs have `vim` but not `nano`. Some have `vi` (the older version) but not `vim`. If you only know `nano`, you're stuck on those systems.
	2. **`vim` is more powerful.** Once fluent, you edit files faster than in any other editor. Search/replace across files, macros, block editing — `nano` can't do these.
	3. **Security-specific uses:**
	    - Editing `sshd_config` on a remote server with only `vim` available.    
	    - Removing a single line from a 10,000-line log file — `vim` is much faster.
	    - Bulk-editing config across dozens of files — `vim` macros make this possible.    
	4. **`vi`/`vim` is standard on almost every Linux system.** Learning it is like learning to drive a manual transmission — you may not use it daily, but when you need it, you'll need it.
- `vimtutor` is an **interactive tutorial** built into `vim`. It's not a man page or a book — it's a **live document** that teaches you `vim` by having you perform exercises inside `vim` itself.
	- **`vim` has modes:**

|Mode|What you can do|
|---|---|
|**Normal mode**|Move around, delete, copy, paste. Keys are commands.|
|**Insert mode**|Type text (like a normal editor).|
|**Visual mode**|Select text.|
|**Command mode**|Run `:` commands (save, quit, search/replace).|

- **When you open `vim`, you're in Normal mode.** If you start typing, nothing gets typed — keys get **interpreted as commands**. This is why beginners think `vim` is broken.
	- **To start typing, press `i`** (for **insert**). Now you can type normally.
	- **To get back to Normal mode, press `Esc`.**
