### What I learned
- In list,we find an item by its postion otherwise known as index and not by name.
- A list is enclosed in square brackets and items are separated by commas
- When you run an Nmap scan, the results are a list of open ports. `[22, 80, 443]`. When you analyze a log, the IPs might be a list.
```
- `ports = [22, 80]` (Creates a list).
- `ports.append(443)` (Adds an item to the end).
- `ports.remove(80)` (Removes a specific item).
- `len(ports)` (Returns the number of items in the list).
```
- In linux, we count from 1 but in python, we count from 0
- When you split a log line (`log.split()`), it becomes a list. To grab the IP address, you need to know exactly which index it is at.
- We can also use the `in` operator to know if an item exists in the list
- A **List Comprehension** is a magical sorting machine: You feed it the box and say, _"Give me every apple that is red."_
	- **The Syntax:**  `[new_item for item in old_list if condition]`
	- It is useful if you have a list of 10,000 scanned ports, but you only want to extract the "open" ones. List comprehensions do this instantly.
- When we write a vulnerability scanner, we will scan 65,535 ports. Most will be closed. You will use a list comprehension exactly like this to filter out the noise and only look at the open ports. It makes your code cleaner and significantly faster.
- json security reports are strcutured using lists of dictionaries. A scanner doesn't output one big blob of text; it outputs a lists of hosts, where each host is a dictionary
```
scans = [
    {"host": "192.168.1.5", "status": "vulnerable", "ports": [22, 80]},
    {"host": "10.0.0.5", "status": "secure", "ports": [443]}
]
```
- To loop through a list of dictionaries:
```
for item in scan_results:
	print(item["ip"])
```
- When you write a tool, you want to be able to export this nested structure so it can be loaded into a dashboard (like Kibana or Splunk) or sent to a client.
- When you query the AWS API, the response looks exactly like your `user_record` dictionary. It will have strings, lists, and nested dictionaries. Being able to chain your keys (`dict["key1"]["key2"]`) is how you extract the specific security data you need without getting lost in the JSON.
- Sometimes, you want your code to crash on purpose. If a user gives you a port number of `"99999"` (which is impossible), you don't want to just return an error message; you want to immediately stop the script and yell at the user. We do this with `raise ValueError("Invalid port number!")`.
- Imagine you are cooking dinner.
	- **`try`**: You try to bake the cake.  
	- **`except`**: If the oven catches fire, you put it out.  
	- **`finally`**: No matter what happens (whether the cake is perfect or the oven caught fire), you **always** wash the dishes and turn off the kitchen light before you leave.
	- The `finally` block _always_ runs. It doesn't matter if the code succeeded, or if it hit an exception.
	- **Why a security engineer cares:**  
		When you open a network socket or a database connection, you want to make sure it gets closed properly. If an error happens mid-connection, `finally` is the guarantee that you clean up your mess.
- In Week 1, you used `try/except FileNotFoundError` to handle missing files. That works, but it means you have to _try_ to open the file and let it fail first. A cleaner, more proactive way is to check if the file exists _before_ you try to open it. We do this using the `os` (Operating System) module.
	- Why is this better than `try/except`? Because it's **proactive**. `try/except` is reactive (you try to open the door, it fails, you handle the crash). `os.path.exists()` is proactive (you look at the door before you touch the handle). In security scripting, it is much cleaner to check if a log file exists before you try to parse it.
	- **The Analogy:**  
	Before you try to open a door, you look at it. If the door isn't there, you don't try to turn the handle; you just say, "The door doesn't exist."
```
import os
if os.path.exists("myfile.txt"):
    print("File exists!")
else:
    print("File missing.")
```
- In Week 1, you learned to write to a file using `"w"` mode. But `"w"` stands for **write**, and it is destructive. If you open a file with `"w"`, it completely erases whatever was already there and starts fresh. So we can use the `a` mode
	- `"w"` is like burning a notebook and buying a new one.  
	- `"a"` is like opening the notebook to the last page and writing a new entry.  
	**Why a security engineer cares:**  
		You never want to erase your logs. When your script detects a new failed login, you want to _append_ it to the end of `alerts.log`, preserving all the previous alerts.
- `json.load` reads a JSON file from hard drive and converts it back into a Python dictionary so we can work with it.
	- `json.dump()` is like packing your clothes into a suitcase.
	- `json.load()` is like opening the suitcase and unpacking your clothes so you can wear them.
	- **Why a security engineer cares:**  
		Imagine you run a vulnerability scan on Monday and save the results to `report.json`. On Tuesday, you write a new script that loads `report.json` to generate a PDF for the client. `json.load()` is how you read the old data back into memory.
- Python is case-sensitive and exact. If the key in the dictionary is `"ports"`, but you ask for `"open_ports"`, Python will throw a `KeyError` and your script dies.
- If the caller wraps the function in a `try/except` block (which you did!), the program doesn't crash. It gracefully catches the error and moves on. The purpose of `raise` is to say: _"I refuse to process this invalid data. Whoever called me has to deal with it."_ `raise ValueError` doesn't automatically "crash the program." It **raises an exception**.
- `finally` runs whether the `try` succeeds or fails. **But** it cannot protect against everything. If the system's power is cut, or an attacker runs `kill -9` on your Python process, the `finally` block will _not_ run. It only runs if the Python interpreter is still alive to process it.
- Use `os.path.exists()` for helpful user messages ("Hey, you forgot to create the file"). But you **must still use `try/except FileNotFoundError`** around the `open()` function, because the file can vanish the moment after you check it.
	 This is a famous cybersecurity concept called **TOCTOU (Time-of-Check to Time-of-Use)**.
	- You check: `if os.path.exists("file.txt"):`
	- Python says: "Yes, it exists!"
	- _A microsecond passes. An attacker (or another process) deletes the file._
	- You try to open it: `open("file.txt")` -> **CRASH.**
- - `"w"` creates a file if it doesn't exist. If it _does_ exist, it truncates it (wipes it to 0 bytes). `"a"` creates a file if it doesn't exist. If it _does_ exist, it writes at the end.
    - **The Security Lesson:** Append (`"a"`) preserves old data, but it is not tamper-proof. An attacker with root can still delete the file or overwrite it with `"w"`. It just means _your script_ won't accidentally erase your logs.
- `json.load()` returns exactly what is at the top level of the JSON file. If the JSON starts with `[...]`, it returns a **List**. If the JSON starts with `{...}`, it returns a **Dictionary**.
