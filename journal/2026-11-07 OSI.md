### What I learned
- The Open systems interconnection is a map that explains how data gets from one computer to another. It has 7 layers.
- Layer 1 is the physical layer. This is the actual hardware. It consists of ethernet cables, fibre optics lines, the Wi-Fi radio waves and the network switches.
	- The physical layer is the physical medium that carries the 1s and 0s
	- The attack surface in this layer is called wire tapping which means entering the server room, cutting open the ethernet cable and attaching a physical device to intercept the electric signals and read the data flowing through it. In the real world, this is rare for a hacker sitting in another country, but very common for spies, rogue employees, or anyone who can sneak into a server room
	-  If an attacker plugs a laptop directly into an internal switch, they completely bypass the external firewall. They are now inside the "trusted" network. They can scan internal servers, sniff unencrypted traffic, and look for open ports that aren't exposed to the internet.
	- In the OSI model, the Physical Layer for Wi-Fi is actually the **radio frequency (RF) waves** in the air. The router is the hardware that _generates_ the waves, but the invisible radio waves themselves are the physical medium (just like the copper wire is the physical medium for a wired connection).
- Layer 2 is the data link layer. This is where computers talk to each other using MAC addresses. If the layer 1 is the road then the layer 2 is like the mail carrier who knows exactly which house on the street gets the letter.
	- A MAC address is a unique, hardcoded serial number burned into every network card e.g.  `00:1A:2B:3C:4D:5E`. 
	- Switches uses these MAC addresses to send data to the exact right computer on the local network.
	- The attack surface in this layer is called ARP spoofing. Computers use ARP (Adddress Resolution Protocol) to match an IP address to a MAc address. However, ARP has no authentication, it blindly trust whoever answers.
	- If an attacker wants to intercept your traffic ,they can send out a flood of fake ARP messages saying "Hey everyone, I am the router! Send all your data to my MAC address!". The computer would blindly trsut this so it send your traffic to the attacker, they read it and then pass it to the real router so that your internet doesn't break. This is also known as Man-in-the-Middle (MitM) attack.
	- ARP is completely trust-based. No authentication, no verification. Whoever answers first wins.
	- **Static ARP entries** (manually hardcoding the MAC address so it can't be changed). It works for small networks, but it's hard to manage at scale. The enterprise solution is called **Dynamic ARP Inspection (DAI)**, where the switch checks the ARP packets to make sure they are legitimate.
	- The entire goal of the Man-in-the-Middle (MitM) attack is to get credential of the victim. Username and password can be seen in wireshark if the victim logs into a website using HTTP whichis unencrypted. If they are using HTTPs which is encrypted, the MitM alone won;t show the password because it is scrambled. Advanced attack like SSL Stripping or a fake certificate would be needed to break the encryption
- Layer 3 is the network layer. It is all about routing. This is where IP addresses live like 192.168.1.5 or 0.0.0.0. If layer 2 is the mail carrier delivering to the specific house on a street then the layer 3 - network layer is the national postal service routing a letter from one state to another. 
	- The network layer basically figures out the best path across the internet.
	- The attack surface here is IP spoofing. This is just like the ARP protocol where there is no authentication, same goes for the IP protocol. You can craft a packet with any source IP address you want.
	- Attackers do this to:
		  1. hide their real identity (the victim sees the traffic coming fro a fake IP)
		  2. bypass firewalls that only allow traffic from a trusted IP
		  3. launch a Denial of Service (DOS) attack (sending 10,000 requests with a fake return address so the server sends all the responses to the victim, flooding them)
	  - IP Spoofing is great for a one-way attack. But because the attacker put a fake return address on the packet, the server sends the response to the fake IP, not to the attacker. So you can send commands, but you can't easily read the replies (unless you are on the same network as the victim).
	  - SYN-ACk won't work with IP spoofing because there would need to be a response then an ACK from the attacker again. Since it's IP spoofing then the attacker does not have access to the ip address he's pretending as so the handshake can't be completed. This is because the attacker is blind to the server's response.
	  - Firewalls rely on IP addresses as a form of identity. If there is no cryptographic authentication (like a VPN or an SSH key), spoofing the "trusted" IP is a classic bypass.
