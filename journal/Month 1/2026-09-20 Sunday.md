### What I learned
- `find` is used to search the system based on some conditions you specify
- find by name searches for file based on the name. `find / -name "passwd" 2>/dev/null` searches for files with the name passwd and moves any stderr to a blackhole.
- to search without case sensitivity, we use `find / -iname "pattern"`
- If we wanna search by type of the file, then use the flags `-type f` for only files, `-type d` for directories and `-type l` for symbolic links. For example, `find /home/darkhand -type f -name "*.log"` finds all regular file ending in .log 
- We can also search by permission using the `-perm` flag
	- The `-` before the number means **"at least these permissions."**
	- `-perm 644` — matches files with exactly 644.
	- `-perm -4000` — matches files with SUID set (plus any other permissions).
	- `-perm -111` — matches files with execute permission for owner, group, and others.
- `-perm -111` means **owner, group, and others** all have execute permission
- `wc` stands for word count. It counts things in a file or from input.
- `wc` gives three numbers. 10 25 150 myfile.txt, 10 stands for number of lines, 25 stands for number of words while 150 stands for number of characters(bytes)
- To use just one number, we use the flags, `-l` for lines, `-w` for words only, `-c` for bytes only and `-m` for characters only (multi-byte characters). The one used mostly would be `wc -l` because log entries are lines
- `cut` extracts **specific columns or fields** from each line of text. By default, `cut` works on **delimited text** — text where fields are separated by a consistent character (like a space, comma, or colon).
- `cut` has two main modes: 1. cut by character position,`cut -c 1-10 myfile.txt` which gives character 1 through 10 of each line and 2. cut by field(delimiter), `cut -d ":" -f 1 /etc/passwd` whic means use : as the delimiter and five me the first field. This prints every username on the system — because in `/etc/passwd`, the first field before the first colon is the username.
- `cut -d ":" -f 1,3 /etc/passwd`. This prints the username (field 1) and the UID (field 3).
- `cut` is used used mainly for log parsing as most log entries have consistent format.
- `sort` sorts lines alphabetically by default however it could also sort numerically or in reverse order using flags. 
- `-n` => Sort numerically (so `2` comes before `10`), `-r` => Reverse order (descending instead of ascending), `-u` => Remove duplicates (unique lines only), `-k` =>Sort by a specific field (column)
- `uniq` removes **adjacent duplicate lines**. It only works on **sorted input**, because it compares each line to the one immediately before it. `uniq` alone, on unsorted input, won't remove duplicates that aren't next to each other. That's why you always pipe `sort` into `uniq`.
- `uniq -c` **counts** how many times each line appears. `sort myfile.txt | uniq -c` - This is how you answer "which IP attacked the most?" — you extract the IPs, sort them, count with `uniq -c`, then sort by count.
- `wc` counts lines/words/bytes. `cut` extracts fields from delimited text. `sort` sorts lines (alphabetically, numerically with `-n`, reverse with `-r`, unique with `-u`). `uniq` removes adjacent duplicates (`-c` counts them). The full log analysis pipeline: `grep | cut | sort | uniq -c | sort -nr` gives a ranked list of attackers.

### Commands/code worth remembering
```code
### The full log analysis pipeline (this is the real power)

bash

grep "Failed password" /var/log/auth.log | cut -d " " -f 10 | sort | uniq -c | sort -nr

Let's break it down:

1. `grep "Failed password"` — filter for failed logins.
2. `cut -d " " -f 10` — extract the IP field.
3. `sort` — group identical IPs together.
4. `uniq -c` — count how many times each IP appears.
5. `sort -nr` — sort numerically in reverse (highest count first).

**Output:** A ranked list of attacking IPs, from most attempts to fewest.
```
