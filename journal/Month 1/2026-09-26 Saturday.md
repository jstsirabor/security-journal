- An attacker aliases `ls` to something like:
	`alias ls='ls --hide=malware.sh'`
	Every time you type `ls`, you see a "clean" directory. But `malware.sh` is still there. You'd have to type `\ls` (with a backslash) or `/bin/ls` (full path) to bypass the alias and see reality.

	`alias`                    # current aliases
	`cat ~/.bashrc`            # check for persistent aliases
	`cat ~/.bash_aliases`      # check if this file exists

### What I learned
- `sed` stands for **stream editor**. It reads text, applies transformations, and outputs the result. Think of it as `awk`'s sibling: `awk` is for extracting and reporting, `sed` is for **editing** text — substitution, deletion, insertion.
- `sed 's/old/new/' file`
	- `s` — substitute.
	- `old` — the pattern to find.
	- `new` — what to replace it with.
	- `/` — delimiter (you can use other characters).
	- Only replaces the first match on each line by default.
- To replace all matches on each line:
	`sed 's/old/new/g' file`
	- `g` — global (all matches, not just the first).
- `sed` with no file (standard input): `echo "hello world" | sed 's/world/there/'`
- `sed` works per line not per file
- `g` means "replace **every** occurrence on **each line**." It's still processing line by line, but now it doesn't stop after the first match.
- `sed 'N d'` deletes lines. You combine it with a **pattern** or **line number** to say _which_ lines to delete.
	`sed '/pattern/d' file`
	This deletes every line that contains `pattern` and prints the rest.
	`sed '5d' file`
	This deletes the 5th line.
	`sed '2,5d' file`
	This deletes lines 2 through 5.
- You can chain multiple `sed` commands together using `-e`:
	`sed -e 's/old/new/' -e '/pattern/d' file`
	Each `-e` adds one command. They run in order on each line.
		`sed -e 's/from/IP:/' -e '/Accepted/d' awk_exercise.log`
		This does two things:
		1. Replaces `from` with `IP:` on every line.
		2. Deletes lines containing `Accepted`.
		Both operations happen in one pass.
- You can also separate commands with semicolons inside one set of quotes:
	`sed 's/from/IP:/; /Accepted/d' awk_exercise.log`
	Same result but the `-e` form is often clearer when commands are long.
- `sed` - In-Place Editing (`-i`) -> Everything so far has printed to the screen. The original file was **never touched**. `-i` edits the file **in place** — meaning it writes the changes back to the file.
	`sed -i 's/old/new/' file`
	This overwrites the original file. There's no undo. If you get the command wrong, the file is damaged. **Safe practice:** Always test the command **without** `-i` first, verify the output, then add `-i`.
- Shell globbing is how you use **wildcards** to match multiple files or patterns without typing every filename.
	`ls *.txt`
	The shell expands `*.txt` into `file1.txt file2.txt file3.txt` before running `ls`.
	- Globbing is done by the **shell**, not by the command. That's why `ls *.txt` works but `grep "*.txt" file` doesn't (grep sees the literal `*`).
- ### The wildcards

| Wildcard             | Matches                                     | Example                                                           |
| -------------------- | ------------------------------------------- | ----------------------------------------------------------------- |
| `*`                  | Any number of characters (including zero)   | `*.txt` matches `a.txt`, `b.txt`, `file.txt`                      |
| `?`                  | Exactly one character                       | `file?.txt` matches `file1.txt`, `fileA.txt` but not `file12.txt` |
| `[abc]`              | Any one character inside the brackets       | `file[123].txt` matches `file1.txt`, `file2.txt`, `file3.txt`     |
| `[a-z]`              | Any character in the range                  | `file[a-z].txt` matches `filea.txt` through `filez.txt`           |
| `[!abc]` or `[^abc]` | Any character NOT in the set                | `file[!0-9].txt` matches `filea.txt` but not `file1.txt`          |
| `{a,b,c}`            | Brace expansion — any of the listed strings | `file.{txt,log,conf}` expands to `file.txt file.log file.conf`    |
- `!!` -> This runs the exact last command you typed. Useful when you forgot to prefix a command with `sudo`:
	`apt install nginx`        # fails, needs sudo
	`sudo !!`                  # runs "sudo apt install nginx"
- `!$` -> This expands to the **last argument** of your previous command.
	`mkdir /tmp/testdir`
	`cd !$`                     # cd /tmp/testdir
- `!42` -> Runs the command with history number 42 (from `history` output).
- `!grep` -> Runs the most recent command that started with `grep`.
- `Ctrl+R` — Interactive reverse search
	This is the most useful one. Press **Ctrl+R** in your terminal, then start typing. It searches your command history and shows matches as you type. Press **Ctrl+R** again to cycle through older matches. Press **Enter** to run the matched command, or **Ctrl+C** to cancel.
- An alias is a **shortcut** for a longer command.
	`alias ll='ls -la'`
	Now, whenever you type `ll`, the shell runs `ls -la` instead.
	**Why a security person cares:**
	- **Speed:** You type less, do more.
	- **Persistence technique:** Attackers use aliases to hide their activity. For example, they might alias `ls` to hide specific files, so when you type `ls`, you see a "clean" directory.
	- **Detection:** If you suspect a system is compromised, check `alias` — unexpected aliases are a red flag.
- To test a security-relevant alias:
	`alias ls='echo "Nothing to see here"'`
	`ls`
	**What happens?** Instead of listing files, `ls` now prints "Nothing to see here."
	**To remove the alias:**
	`unalias ls`
	`ls`
	**Now `ls` works normally again.**
- Aliases defined in the terminal are only for that session. When you close the terminal, they're gone.
- **To make aliases persistent**, add them to `~/.bashrc` (or `~/.bash_aliases`). They'll load every time you open a new terminal. **Attackers do this too.** They add an alias to `~/.bashrc` so it persists across reboots.
- `strings`, `file`, `xxd` -> These three tools help you analyze **unknown files** — which is core incident-response work.
