### What I tried
- The command to find all SUID bit on the root filesystem is `find / -perm -4000 2>/dev/null`. This is used to identify which programs have SUID set. If any of them are on GTFOBins, they might be exploitable for privilege escalation.
- SUID (Set Owner User ID) makes a program run with the file owner's permissions. `/usr/bin/passwd` has SUID so normal users can change their passwords (writing to `/etc/shadow` as root). SUID is dangerous when the program can read/write arbitrary files or spawn a shell. `find / -perm -4000 2>/dev/null` finds all SUID binaries. GTFOBins lists binaries that can be abused for privilege escalation — search by name, not full path.

### What I learned
- SUID stands for **Set Owner User ID**. It's a special permission bit on a file.
- With SUID set, the program runs with the **file owner's** permissions — not yours. If the file is owned by `root`, the program runs as `root`, no matter who launches it.
- SUID on `passwd` is safe because it's single-purpose — it only touches `/etc/shadow` in a controlled way to update the password hashes in `/etc/shadow`. SUID on a text editor is dangerous because it can open, edit, and save ANY file, including `/etc/shadow`. The danger isn't about spawning shells — it's about arbitrary file read/write with elevated privileges.
