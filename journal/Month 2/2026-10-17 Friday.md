### What I learned
- A bash script is a text file containing a series of commands, meant to be run as a program.
```
#!/bin/bash
echo "Hello, world"

Line 1: `#!/bin/bash`** — the "shebang." It tells the system which interpreter to use. Without it, the system doesn't know whether to use bash, sh, python, or something else.

**Line 2:** a normal command.
**To run it:**

chmod +x myscript.sh
./myscript.sh
```
- A variable is a **named box holding a value**.
	name="Darkhand"
	age=23
	**Critical rule:** No spaces around the `=`. `name = "Darkhand"` is wrong. `name="Darkhand"` is correct.
	
	bash
	echo "$name"
	echo "Age: $age"
		The `$` before the name tells bash to **expand** the variable to its value.
	**Without quotes:**
	bash
	echo $name
		
	This works, but it's fragile. If the value contains spaces, it will be split into multiple words.
	**With quotes (the correct way):**
	bash
	echo "$name"
	
	- Always quote your variables unless you specifically want word-splitting.
- When you run a script with arguments, those arguments are stored in **positional parameters**.
	./myscript.sh hello world

	Inside the script:

|Parameter|Value|
|---|---|
|`$0`|`./myscript.sh` (the script itself)|
|`$1`|`hello` (first argument)|
|`$2`|`world` (second argument)|
|`$@`|`hello world` (all arguments)|
|`$#`|`2` (number of arguments)|
|`$?`|exit code of the last command|
- Both `$@` and `$*` represent all arguments, but they behave differently.
	- **`$@`** — expands to separate, individually quoted arguments. `"$@"` = `"Alice" "Bob" "Charlie"`.
	- **`$*`** — expands to a single string. `"$*"` = `"Alice Bob Charlie"`.
- Use `"$@"` (with quotes) almost always. It correctly preserves arguments with spaces.
- `$?` holds the **exit code** of the last command.
	- `0` — success
	- Non-zero — failure (the specific number varies)
- You can prompt for input with `read`
```
- `${1}` means "the first argument."
    
- `:-` means "if that variable is empty or unset, use the following default instead."
    
- `none` is the default value.
    

So `${1:-none}` means:

> "Print the first argument. But if no first argument was provided, print the word 'none' instead."

It prevents the script from printing an empty blank space when you run it without arguments.
```
