### What I learned
- Running `sudo` seeks to use the privilege of root hence a security check is  performed to ensure you are the who you say you are and have the permission to act as root
- `sudo` doesn't just give root privilege instead it consults a file called `/etc/sudoers` to know exactly who can run what as whom. It's tied closely yo the the `principle ofleast privilege` in which a user is granted permission to only run some specific commands without giving them full access.
- The command `sudo -l` list all the possible commands a user is allowed to run with `sudo`. It is also one of the commands an attacker runs when they get access to a user account as it reveals every possible privilege escalation path
```
User darkhand may run the following commands on darkhand:
    (ALL : ALL) ALL
    (root) NOPASSWD: /usr/bin/mintdrivers-remove-live-media
    (root) NOPASSWD: /usr/bin/mintdrivers-load-broadcom-modules
    (root) NOPASSWD: /usr/bin/mint-refresh-cache
    (root) NOPASSWD: /usr/lib/linuxmint/mintUpdate/dpkg_lock_check.sh
    
The ALL tells me that I can run every command with root privilege however the other rootNOPASSWD says no password is required to run those as root hence they are potential privilege escalation path.

When you see `sudo -l` output, for each entry ask:
1. Is the script **writable** by my user?
2. Does it call **external commands** that can be hijacked via `PATH`?
3. Does it use **libraries** that can be injected via environment variables like `PYTHONPATH`, `PERL5LIB`, etc.?
```
