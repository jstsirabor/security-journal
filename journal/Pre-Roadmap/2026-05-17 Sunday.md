- I did a task:
```bash
The task was to write a script called `scan_logs.sh` that:
1. Takes a directory as an argument.
2. If no argument, prints usage and exits.
3. If not a directory, prints error and exits.
4. Loops over every `.log` file in that directory.
5. For each file, prints a header `=== filename ===` and counts how many lines contain `Failed`.
6. If no `.log` files exist, says so.
7. After the loop, prints `Scan complete.`
   
#!/bin/bash

if [ -z "$1" ]; then
   echo "Usage: scan_logs.sh <directory>"
   exit 1
fi
if [ -d "$1" ]; then
   found=0
   for file in "$1"/*.log; do
        if [ -f "$file" ]; then
            echo "=== $file ==="
            grep -i -c "failed" "$file"
            found=1
        fi
   done
   if [ $found -eq 0 ]; then
        echo "No log files found."
   fi
else
   echo "The directory does not exist"
   exit 1
fi
echo "Scan complete."

Why the flag is better:  
It separates concerns. The -f test inside the loop only decides "is this a real file?" — it doesn't also carry the responsibility of printing a message. The flag records the _fact_ that we processed at least one real file. After the loop, we use that fact to decide whether to print the "No log files" message. This is cleaner and easier to read, especially as scripts grow more complex.
```

- To iterate over multiple inputs using the same function
```bash
check_file() {
	if [ -z "$1" ]; then
		echo "Usage: check_file <filename>"
		return 1
	fi
	if [ -f "$1" ]; then
		echo "$1 exists"
		wc -l < "$1"
	else
		echo "$1 does not exist"
		return 1
	fi
}
if [ $# -eq 0 ]; then
	echo "Usage: check_files <file1> [file2] ..."
	exit 1
fi
for file in "$@"; do
	check_file "$file"
	if [ $? -ne 0 ]; then
		echo "There was a problem with $file"
	fi
done
```
- When working on a file name, it's proper to put it in double quotes to avoid error if the filename includes spaces
- `$@` picks all inputs at the same time
- `$#` returns the number of inputs that's given by the user
- `$?` is a special variable that holds the **exit status** of the last command that ran. In bash, a command that succeeds returns 0; a command that fails returns a non‑zero value (usually 1). When a function uses `return 1`, the caller can check `$?` immediately after the function call to decide what to do next.
- I ran `find / -user bandit7 -group bandit6 -size 33c >/dev/null`. However this send the output i want into the void and keeps the error. To solve this we use the command `find / -user bandit7 -group bandit6 -size 33c 2>/dev/null`. This happened because the flood of "Permission denied" messages go to standard error, which you see. You want the opposite: suppress the errors, keep the output. So you need `2>/dev/null` (redirect stderr). This keeps the terminal clean and results usable.

### What I learned
- A software package is a group of files - typically libraries and other dependencies - that you need for a piece of software to run successfully.
- `apt` means advanced packaging tool and the primary command is `apt-get` which you can use to download, install, update and upgrade software with it
- To check if a package is available e.g. snort, we use the apt search function. `apt-cache search snort`. If it exist, we can use `apt-get install snort`. To remove,  we can use `apt-get remove snort`. However, if we want to remove both the package and the configuration, we can use the `apt-get purge snort`
- Updating updates the list of packages available for download from the repository whereas Upgrade will upgrade the package to the latest version in the repository. To do this, we use `apt-get update` and `apt-get upgrade`. root permission for both is required.
- We can add repositories to get more packages if unavailable by editing the `/etc/apt/sources.list`
- Newer version of Kali no longer have a GUI-based software installation tool however we can download them. The two most common are synaptic or gdebi
- Sometimes the software we want isn't available on any repository perhaps because it's new but it may be available on github - a site that allows developer to share their software with others to download use and provide feedback. For instance, if we download bluediving, a bluetooth hacking and pentesting suite and can't find it in the kali repository, we can install it by cloning it from github using the command `git clone https://www.github.com/balle/bluediving.git` and a new directory will be created for it
- `return` signals failure to the _caller_ without killing the whole script, so the loop can continue with the next file.
