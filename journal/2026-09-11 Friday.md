### What I tried
- Touch creates a file if it doesn't exist and updates the timestamp if it does exist but  doesn't change the content.
- Linux files have three timestamps: atime (access), mtime (modify), and ctime (change/metadata). `touch` can change atime and mtime, but ctime always updates to the current time when metadata changes. Investigators can detect timestomping by comparing mtime and ctime — if mtime is older than ctime, the timestamp was likely faked.
- `mkdir` creates directories. By default, it only creates the final directory in the path — if parent directories don't exist, it fails. The `-p` flag creates the entire chain of parent directories as needed.
- `less` can execute shell commands using `!command`. If run with `sudo`, this can lead to privilege escalation — a user can spawn a root shell from inside `less`. This is a known GTFOBins technique.

### What I learned
- Timestomping: Attackers use `touch -t` to set a false timestamp on malicious files, so they don't appear in a time-window search during incident response. This hides them from forensic timeline analysis. 
```
touch -t 202301010000.00 myfile.txt

This sets the timestamp to:

- 2023 — year
- 01 — month (January)
- 01 — day
- 00 — hour
- 00 — minute
- .00 — seconds

So it sets the file's mtime to January 1, 2023 at 00:00:00.
```
- If your colleague runs `sudo less /etc/shadow`, they _could_ type `!bash` and get a root shell. You'd be right to be concerned.
- `less` can open files that are still being written to. You can run: `less /var/log/auth.log` And even while the log is actively growing, `less` will show you the file. Press `Shift+F` inside `less` and it will **follow** the file, like `tail -f` but inside the pager. So you can watch logs, search them, and follow them — all in one tool. The downside however is if you `sudo less` a sensitive log, you're now in a root-privileged pager that can execute commands. Same escalation risk.
- `head` shows the first lines of a file. Security use: checking magic numbers to identify file types (e.g., ELF binaries disguised as images). The command is `head -c 10 /bin/ls | xxd`
- `tail -f` follows a file in real time. But if the file is rotated (logrotate), `tail -f` keeps following the old file. Use `tail -F` to follow the file by name, so it switches to the new file after rotation.
- Attackers can disrupt logging without deleting logs: (1) force log rotation so malicious entries move to archived files, `logrotate -f /etc/logratate.conf` (2) fill the disk so no new logs can be written by flooding the system with activity that generates logs until `/var` is full. (3) stop or restart the logging service to create gaps, `systemctl restart rsyslog (or systemctl stop rsyslog)` (4) Kill the logging process, `kill -9 <pid_of_rsyslog>`. Defense: forward logs to a central server the attacker cannot access.
- Real-time log monitoring with `tail -f` allows immediate response: blocking IPs, disabling accounts, or isolating the server while the attack is happening. After-the-fact log review only allows reporting — the attack is already over.
