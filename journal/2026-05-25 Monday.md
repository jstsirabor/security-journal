### What I learned
- Users in a group all inherit the same group permissions
- There are three types of permissions: permission to read which involves opening and viewing a file, permission to write which is viewing and editing and permission to execute the file but not necessarily view or edit it.
- To grant permission of a file to a user, we use the `chown` command which means change owner. For instance, `chown bob /tmp/bobsfile`. To do the same but for groups, we use the command `chgrp`, for instance `chgrp security newIDS`
- When we run`ls -l`, we cam see the number of links just after the permission for the owner, group and other users.
- Users can have permission to execute only either binaries or scripts
- Full meaning of the command `chmod` is change command
- Apart from chmod octal numeric method of chaginng permission, we can use the UGO method. This works by adding the command like `-` which  is to remove a permission, `+` to add a permission and `=` to set a permission. Changing the permission of a user uses `u` while group uses `g` and other users use `o`. Now to  add a execute permission to an user, we can use the command `chmod u+x file` while for a group would be `chmod o+x file`. You can also join commands, for instance `chmod u+x, o+x hashcat.hcstat`
- Linux automatically assigns base permissions—usually 666 for files and 777 for directories.
- Linux  has 3 special permissions, SUID (set user ID), SGID (set group ID) and sticky bit. SUID uses 4 such as `chmod 4664`, SGID uses 2 such as `chmod 2644` while sticky bit was used in outmoded UNIX systems
- Privilege escalation is the process where a user gains root or sysadmin privileges and the associated permissions.
- To look for files with the SUID bit, we can use the find command `find / -user root -perm 4000`
- A file with SUID bit set can be a potential attack vector
