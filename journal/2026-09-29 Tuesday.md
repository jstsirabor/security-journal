### What I learned
- `lsof` stands for list open files. It shows every file that's currently open by any process — including network sockets, which Linux treats as files.
- `lsof -i` shows network-related open files (i.e., network connections).
	- `sudo lsof -i` -> root access
	- **Filter by port:**
		`sudo lsof -i :22`
		`sudo lsof -i :4444`
	- **Filter by protocol:**
		`sudo lsof -i tcp`
		`sudo lsof -i udp`
	- **Filter by user:**
		`sudo lsof -u darkhand -i`
	- **Why `lsof -i` is useful**
		- Find which process is using a port. If `ss` tells you port 4444 is listening, `lsof -i :4444` tells you which process and PID is behind it.
		- Find all network activity for a user.
		- Investigate suspicious outbound connections — e.g., a process talking to an unfamiliar external IP.
- **The real reasons `ss` might show a port that `lsof` doesn't:**
	1. **Most common:** The process **exited between the two commands**. You ran `ss`, saw port 4444, then the process died before you ran `lsof`. `lsof` sees nothing because nothing's there anymore.
	2. **Network namespace:** If the service is inside a container (Docker, etc.), `ss` on the host might see the socket, but `lsof` might not be able to see the process because it's in a different namespace.
	3. **Time-Wait / Close-Wait state:** The socket is in a closing state. `ss` still reports it as `LISTEN`, but `lsof` might not show it as an active process.
```
- `ss` shows **network socket statistics** — what's listening, what's connected, in what state. Fast, focused on networking only.
- `lsof -i` shows **open files that are network-related** — every process that has a network socket open. Slower, but gives **more per-process detail** (FD number, size/offset, node info).

**When to use each:**
- `ss` — quick check. "What's listening? What's connected?"  
- `lsof -i` — deeper. "Which exact process, user, and file descriptor is behind this connection?
  
**They overlap but aren't identical.** Use both in real investigations.
```
